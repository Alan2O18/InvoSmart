# V0.0.22 系統修復與模板管理升級 結案報告

## 執行摘要
本次版本 (V0.0.22) 主要針對 V0.0.20 與 V0.0.21 版本迭代中遺留的系統錯誤進行緊急修復，並對系統的「蓋章模板管理」進行了視覺化介面的大幅度升級，正式淘汰了過去讓使用者直接手寫 JSON 的反直覺設計。

## 1. 系統層面與後端 API 修復
### 1.1 解決 `/api/pdf-tasks` 路由失效 (404 Not Found)
* **問題描述**：V0.0.21 完成了獨立 PDF 任務的後端實作 (`pdf_tasks.py`)，但未在主程式正確註冊。
* **修復方式**：將 `pdf_tasks_router` 獨立抽出 `__init__.py` 的嵌套，並在 `backend/main.py` 中直接掛載至 `/api` 前綴。
* **成果**：前端已可正確存取並建立獨立 PDF 任務。

### 1.2 解決印章管理報錯 (500 Internal Server Error)
* **問題描述**：V0.0.20 將印章模型由 `group_name` 綁定改為 `owner_id` (與 Person 關聯)，但底層 SQLite Schema 未同步更新，導致 API 查詢崩潰。
* **修復方式**：撰寫並執行 `scripts/upgrade_db_v0_0_20.py` 腳本，強制 Drop 舊版的 `stamps` 與 `groups` 資料表，並透過 `init_db()` 自動重建符合新版 `owner_id` 關聯架構的資料表。
* **成果**：成功進入「印章與人員管理」頁面，且 API 恢復正常連線。

## 2. 前端介面 UI/UX 升級
### 2.1 全新圖形化模板編輯器 (`StampTemplateEditorView.vue`)
* **問題描述**：在先前的實作中，使用者必須在「管理中心」的表單中手動輸入 `{"default": {"x": 420, "y": ...}}` 的 JSON 字串來配置蓋章位置。
* **改動細節**：
  * 新增了專屬的編輯器頁面，採用 HTML5 Canvas 提供以 A4 比例為基準的即時預覽畫布。
  * 實作了角色清單切換（包含經手人、指導老師、騎縫章等），點擊後可透過表單設定該角色的 `x, y, w, h`。
  * 當座標改變時，左側畫布會即時更新矩形預覽框。
* **路由更新**：在 `router/index.js` 加入了 `/stamp-templates/create` 與 `/stamp-templates/:id/edit` 兩條新路徑。

### 2.2 簡化管理中心 (`StampsManagementView.vue`)
* **改動細節**：
  * 徹底移除了底部的 JSON 填寫表單。
  * 改為乾淨的「新增視覺化模板」按鈕。
  * 在既有的模板卡片列表中，加入了「編輯模板」的按鈕，供使用者點選後跳轉至新的視覺化編輯器進行修改。

## 後續待修復問題預告 (V0.0.23)
雖然 V0.0.22 修復了路由與資料庫舊表的問題，但在測試過程中發現了更底層的 4 項嚴重缺陷，這些將在下一階段 **V0.0.23** 集中處理：
1. `main.py` 啟動時發生 `AsyncSessionLocal` 引用錯誤，導致虛擬角色建立失敗，連帶導致印章無法順利綁定至這些角色。
2. PDF 任務上傳後，瀏覽器遇到 `Content-Disposition: attachment` 而強迫下載，無法在系統內預覽。
3. `VoucherGenerator` 與 `pdf_tasks` 中的印章蓋印邏輯，實際上並未真正實作圖片的隨機旋轉，僅留有標記。
4. `StampTemplateEditorView` 的畫布目前仍為單純色塊，尚未實作抓取真實印章圖片進行高擬真預覽的功能。
