# v0.0.22 系統修復與模板管理升級

**專案狀態**: ✅ 已完成

---

## 執行摘要

v0.0.22 主要聚焦在 v0.0.21 遺留問題的緊急修補，並把蓋章模板管理從純文字 JSON 輸入升級為可視化編輯流程。這一版的重點不在擴張新業務線，而是把既有 PDF 任務、印章管理與模板管理的路徑補齊到可實際使用的狀態。

---

## 主要完成項目

### 1. 修復 PDF 任務路由註冊
- 將 `backend/routers/pdf_tasks.py` 正式掛載進 `backend/main.py` 的 FastAPI 路由表。
- 讓 `/api/pdf-tasks` 與其子路由恢復可用，前端可正常進行任務建立、列表與編輯。

### 2. 修復舊版資料表導致的印章管理錯誤
- 新增資料庫升級腳本 `scripts/upgrade_db_v0_0_20.py`。
- 透過清除舊版 `stamps`、`groups` 資料表並重建新版 schema，讓 `owner_id` 關聯的印章管理流程恢復正常。

### 3. 升級蓋章模板管理 UI
- 新增 `frontend/src/views/StampTemplateEditorView.vue` 視覺化模板編輯器。
- 在 `frontend/src/router/index.js` 新增 `/stamp-templates/create` 與 `/stamp-templates/:id/edit`。
- 將 `StampsManagementView.vue` 的模板管理從 JSON textarea 改為「新增視覺化模板」與「編輯模板」入口，降低使用門檻。

---

## 版本結果

- PDF 任務路由可用。
- 印章與人員管理頁面可正常進入。
- 蓋章模板管理改為圖形化編輯流程。
- v0.0.22 之後又延伸出更底層的 0.0.23 嚴重缺陷修補計畫，用於處理虛擬人員初始化、PDF 預覽與蓋章旋轉等問題。
