# 版本紀錄 - v0.0.18 (FileOps 解耦 + 匯出規格修正 + DB 正規化)

日期：2026-04-20

---

## 🎯 重點更新 (Key Focus)
本版完成 v0.0.18 主計畫四大目標：
- 匯出命名/活動名稱/分類排序規格修正
- Excel 空表來源修正（改為 DB 即時讀取）
- FileOps 完整拆分為 ImageService + CacheService（移除舊檔）
- Job 資料模型改為「正規化欄位 + InvoiceItem」主體，並提供一次性遷移腳本

## ✨ 主要更動 (Implemented)

### 1) Export Logic Refinement
- `backend/processing/flattening.py`
  - 新增分類排序權重：`保險 > 膳食(課程會) > 餐食 > 茶水 > 消耗性教材 > 其他字元排序`
  - `aggregate_flattened_jobs` 在輸出前排序 `allFlattenedItems`，確保 Word 合併列時同類連續
  - 新增 `build_export_payload_from_db(...)`，支援以 DB 查詢結果即時組裝匯出 payload

- `backend/engine/word_exporter.py`
  - `{{活動名稱}}` 改為 `"{project_id} {活動名稱}"`
  - 移除對 `flattened_data` 檔案快取依賴，改為每次即時由 `get_display_result` 組裝
  - 輸出檔名改為：`[ProjectID]「[ProjectName]」_預結算表_{YYYYmmdd_HHMMSS}.docx`
  - 檔名套用 Windows 非法字元清理：`[<>:"/\\|?*] -> _`

- `backend/engine/excel_exporter.py`
  - 以 `list_jobs + get_job + get_display_result` 即時讀資料，不依賴 `manual_json_text/flattened_data`
  - 檔名改為：`[ProjectID]「[ProjectName]」_預結算表_{YYYYmmdd_HHMMSS}.xlsx`
  - 套用相同非法字元清理規則

### 2) DB Schema & Repository Refactor
- `backend/database/models.py`
  - `Job` 新增欄位：`voucher_id`, `purpose`, `supplier`, `invoice_date`, `total_amount`
  - `vlm_result_json` 改為 `vlm_raw_json`
  - 移除模型欄位：`manual_json_text`, `flattened_data`, `flattening_status`
  - `manual_updated_at` 保留

- `backend/repositories/job_repository.py`
  - 移除雙重事實來源縫合流程（不再保存完整 manual JSON blob）
  - 新增：
    - `_extract_header_fields(json_data)`
    - `_reconstruct_display_json(job, items)`
    - `delete_invoice_items(job_id)`
    - `list_invoice_items(...)`, `list_invoice_items_for_jobs(...)`
  - 改寫：
    - `complete_vlm(...)`：寫 `vlm_raw_json` + 正規化欄位 + `InvoiceItem`
    - `save_manual_json(...)`：只更新正規化欄位與 `InvoiceItem`，不再儲存完整 manual JSON
    - `get_display_result(...)` / `get_job_details(...)`：由 DB 即時組裝前端相容 JSON
    - `get_job(...)`：保留舊 key 相容（`vlm_result_json` 映射至 `vlm_raw_json`）

- `scripts/migrate_v0_0_18.py`（新）
  - 一次性遷移腳本：
    - 補齊新欄位（若缺）
    - `vlm_result_json -> vlm_raw_json` 回填
    - 從 JSON 回填 `voucher_id/purpose/supplier/invoice_date/total_amount`
    - 缺漏時重建 `invoice_items`
    - 清空舊欄位內容：`manual_json_text/flattened_data/flattening_status`

### 3) Export Pipeline Adaptation
- `backend/engine/export.py`
  - 移除 `precompute_flatten_cache`

- `backend/routers/jobs.py`
  - 移除 `save_manual_json` 後台 precompute flatten cache 任務

### 4) FileOps Complete Decoupling
- 新增：
  - `backend/engine/image_service.py`
  - `backend/engine/cache_service.py`

- 更新：
  - `backend/engine/file_service.py`
    - 新增共用路徑工具：`_resolve_project_path`, `_is_within_root`
  - `backend/engine/core.py`
    - `self.file_ops` 全面替換為 `self.image_service` + `self.cache_service`
    - 相關 delegate 方法改綁定新 service
  - `backend/routers/files.py`
    - preview 改呼叫 `engine.cache_service.ensure_preview_cache`
  - `backend/routers/voucher.py`
    - preview 改呼叫 `engine.cache_service.ensure_preview_cache`

- 旋轉重置流程更新（`ImageService.rotate_image`）
  - 改為：
    1. `delete_invoice_items(job_id)`
    2. `status=ready`
    3. `vlm_raw_json=None`
    4. `voucher_id/purpose/supplier/invoice_date/total_amount=None`
    5. 清理 `validation_json/vlm_stats/qr_verified/manual_updated_at`

- 刪除：
  - `backend/engine/file_ops.py`
  - `backend/engine/cache_mixin.py`

## 🧩 補遺（2026-04-24）- 全量測試 12 錯誤修復批次

### 補遺背景
在 v0.0.18 主改版（服務拆分 + DB 正規化）後，針對全量 `pytest -q` 進行回歸時，出現 **12 個失敗**（其餘 512 通過）。

失敗主要集中在「舊測試假設」與「新架構實作」的介面落差，包含：
- 既有測試仍直接使用 `engine.file_ops` 屬性
- 舊版 Job 欄位/建構參數仍被測試依賴（`vlm_result_json`, `manual_json_text`, `flattened_data`, `flattening_status`）
- repository 對舊版 manual payload 的回傳語意不一致
- voucher 預覽路由在 mock 條件下，對新/舊 preview provider 的選擇邏輯不相容

### 本次修補策略（Compatibility-First，不回退 v0.0.18 核心設計）

#### 1) 匯入路徑與舊模組相容回補
- 新增 `backend/engine/file_ops.py`：
  - 作為 **legacy compatibility shim**，底層委派給 `ImageService` / `CacheService`
  - 保留舊測試仍會 patch/呼叫的介面形狀（例如 rotate reset 行為）

- 新增舊腳本入口：
  - `scripts/migrate_db_flatten_jobs.py`
  - `scripts/migrate_images_to_jxl_avif.py`
  - 目的：恢復舊測試/工具鏈依賴的 import path（避免 collection/import error）

#### 2) Engine 與 Router 的雙介面相容
- `backend/engine/core.py`
  - 回補 `self.file_ops = self.image_service` 別名，維持舊測試可 patch 的掛點
  - `cleanup_preview_cache` 等流程可透過相容別名運作，兼容舊測試預期

- `backend/routers/voucher.py`
  - thumbnail preview 服務選擇改為新舊雙路徑容錯：
    - 優先新式 `cache_service`
    - 必要時 fallback 到 legacy `file_ops`
  - 增加對 mock 場景 async/sync callable 的穩健處理

#### 3) Job 模型欄位相容層回補
- `backend/database/models.py`
  - 在保留 v0.0.18 正規化欄位（`vlm_raw_json` + header/summary columns）的前提下，
    回補舊欄位供相容用途：
    - `vlm_result_json`
    - `manual_json_text`
    - `flattened_data`
    - `flattening_status`

#### 4) Repository 行為相容（雙欄位 / 舊 payload 語意）
- `backend/repositories/job_repository.py`
  - `get_job`：加入 `vlm_raw_json` / `vlm_result_json` 雙向 fallback
  - `update_job`：同步支援 legacy 欄位 alias 與 flatten 欄位狀態
  - `complete_vlm`：寫入新欄位同時維持舊欄位可讀性，並清理過時 manual blob
  - `save_manual_json`：對 legacy-shaped payload 保留舊欄位相容語意
  - `get_display_result`：補上舊 manual payload 可重建路徑
  - 狀態重設（非 done）時，確保 `flattened_data/flattening_status` 一併清理
