## 🎯 重點更新 (Key Focus)
本版修正兩個互動式影像裁切元件的「座標漂移 (Coordinate Drift)」問題，並為手動二切視窗導入完整的 Pan & Zoom 功能，大幅提升精細對位的操作體驗。

> **根本原因 (v0.0.19-fix)**：
> `preview/raw` 端點回傳的是最大 800px 的縮圖，但後端偵測（`detect_raw_sub_rects`）是在**原始全尺寸圖**上執行，
> 座標為全尺寸像素。前端將這些座標直接畫在縮圖的 SVG 上，導致框框超出邊界（全尺寸 3000px 的框 → 800px 的 viewBox）。
> 後端裁切仍在全尺寸圖上進行所以是正確的，但前端顯示完全錯誤。

## ✨ 主要更動 (Implemented)

### 1) ResplitModal.vue — 全面重寫

#### 根本原因修正
- **舊問題**：使用 `object-fit: contain` 導致 `<img>` 包含黑邊補白 (Letterboxing)。SVG 覆蓋層對齊的是含黑邊的 `clientWidth`，而非真實的圖片渲染區域，造成控制點座標嚴重偏移與超出邊界。
- **修正方式**：
  - 移除 `object-fit: contain`，改為 `.transform-layer` 固定為圖片的原始 `naturalWidth × naturalHeight` 尺寸。
  - `<svg>` 設定 `viewBox="0 0 naturalWidth naturalHeight"` + `preserveAspectRatio="none"`，使 SVG 座標單位與圖片自然像素完全 1:1 對齊。
  - 多邊形端點座標直接以自然像素儲存，SVG 透過 viewBox 自動映射，**零轉換誤差**。

#### Pan & Zoom 導入
- **滑鼠滾輪（`@wheel`）**：以游標位置為中心進行縮放，利用 `(ox - tx) * ratio` 公式更新 translate，確保縮放中心不漂移。
- **空白鍵（Space）+ 左鍵拖曳**：切換為平移模式，移動 `.transform-layer` 的 `translate(x, y)`。
- **縮放範圍**：5% ~ 1000%（MIN_SCALE 0.05 ~ MAX_SCALE 10）。
- **還原視角（Fit to Screen）按鈕**：自動計算最佳初始縮放比例並置中。
- **UI 放大/縮小按鈕**：以視口中心為縮放基點，提供鍵盤友好的替代操作。

#### 拖曳座標精準推算
- `screenToNatural(clientX, clientY)` 公式：
  ```
  naturalX = (clientX - hostLeft - translate.x) / scale
  naturalY = (clientY - hostTop  - translate.y) / scale
  ```
  正確反推在任意縮放/平移狀態下的自然像素座標，並 Clamp 至 `[0, naturalWidth]` 範圍。

#### 其他改善
- `vector-effect: non-scaling-stroke` 使 SVG 邊框線寬在縮放時保持固定視覺粗細。
- `handleRadius` 動態計算為 `8 / scale`，確保控制點在縮放後大小一致。
- 平移模式下游標自動切換為 `grab` / `grabbing`，提供直覺的 UI 回饋。
- 按 Space 時暫停控制點拖曳，避免衝突。

### 2) StampAssignDialog.vue — 座標映射精準化

#### 根本原因修正
- **舊問題**：`getStageMetrics()` 對 `stageRef`（含有 `border: 1px solid`）呼叫 `getBoundingClientRect()`，導致 `rect.width` 比實際圖片渲染寬度多出 2px，`scaleX` / `scaleY` 計算比例失真，原始圖片越大漂移越明顯。
- **修正方式**：
  - 移除 `getStageMetrics()`，改為 `getImageMetrics()`：對照到 `imageRef`（純 `<img>` 元素，零 border/padding）取 `getBoundingClientRect()`。
  - `startDraw` / `moveDraw` / `cancelDraw` / `finishDraw` 全部改用新方法。
  - `finishDraw` 中 `scaleX = naturalWidth / imageRect.width`，排除外框干擾，比例計算精準。

## 🔥 Hotfix (2026-04-29) — 拖曳不跟手 & dist 過期

### 問題 1：ResplitModal 控制點拖曳不跟手
- **根本原因**：`mousemove` / `mouseup` 事件綁定在 `.canvas-host` 元素上（Vue template 的 `@mousemove`）。
  當使用者快速拖曳控制點，游標移出 `.canvas-host` 邊界時，事件停止觸發，端點瞬間凍結，造成「不跟手」感。
  原本程式碼的注解寫「mousemove still fires on window」，但實際根本沒有把監聽器掛到 `window`。
- **修正方式（`ResplitModal.vue`）**：
  - 移除 template 上的 `@mousemove`、`@mouseup`、`@mouseleave` 屬性。
  - `startDrag()`（控制點開始拖曳時）→ `window.addEventListener('mousemove', onWindowMouseMove)`
  - `onHostMouseDown`（Space + 左鍵平移時）→ 同上掛載到 `window`
  - `onWindowMouseUp` 執行時：結束拖曳並 `window.removeEventListener(...)` 清理。
  - `detachListeners()` 也同步清理，防止 modal 關閉時記憶體洩漏。

### 問題 2：`dist` 靜態建構過期
- **根本原因**：`frontend/dist/` 自 v0.0.19 初版修改後從未重新 build。
  舊 dist 仍包含 `object-fit: contain`、無 Pan/Zoom、無 `fullImageSize` 全解析度映射（即 v0.0.18 的舊版程式）。
  若從 `dist` 靜態目錄存取前端，等同完全繞過 v0.0.19 的所有修正。
- **修正方式**：執行 `npm run build` 重新建構，`dist` 現已包含所有 v0.0.19 + Hotfix 的最新程式碼。

## ✅ 驗證方式

### 手動驗證
1. **ResplitModal**
   - 載入後，偵測出的多邊形框必須完美貼齊發票邊緣，不出界、不進黑邊。
   - 滾輪縮放，游標為中心，畫面不漂移。
   - Space + 拖曳可平移視角，放開 Space 可繼續調整端點。
   - 套用後，新分割出的圖片與框選範圍一致。
2. **StampAssignDialog**
   - 上傳印章圖紙，框選一個印章，確認虛線邊界與切割結果完全重疊。
   - 測試原始影像為大尺寸時（如 A4 掃描 300dpi），確認漂移已消除。
