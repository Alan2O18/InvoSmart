# v0.0.14

日期：2026-04-04

## 1. 主題

儲存空間清理 + 手動二切工具（後端流程與前端操作閉環）

本版聚焦兩件事：

1. 降低歷史圖片與預覽快取造成的儲存膨脹。
2. 提供可控的手動二切流程，讓使用者能對單一 job 進行細切並取代舊資料。

---

## 2. 實作摘要

### 2.1 JXL 編碼參數化（lossless / effort）

- 檔案：`backend/processing/jxl_encoder_backend.py`
- 調整：
  - `encode_image_to_jxl(...)` 新增 `lossless` 與 `effort` 參數。
  - 針對不同 `imagecodecs` 版本提供參數回退邏輯（`distance/level/default`）。
- 檔案：`backend/processing/image_codec_adapter.py`
- 調整：
  - Adapter 讀取 `processing_settings.jxl_encode`（或兼容鍵）並傳遞給 JXL 編碼器。

### 2.2 停用自動方向旋轉

- 檔案：`backend/processing/perspective_transform.py`
- 調整：
  - `fix_orientation` 改為相容保留但不執行自動旋轉，避免投影啟發式誤判導致內容方向錯置。

### 2.3 ReceiptSplitter detect-only 能力

- 檔案：`backend/processing/receipt_splitter.py`
- 調整：
  - 新增 `detect_only(image)`，只輸出候選區域四點與面積，不裁切。
  - 抽出 `_detect_rects(...)` 供 `split(...)` 與 `detect_only(...)` 共用偵測流程。

### 2.4 FileOps/Engine：清理、刪檔、優化、二切

- 檔案：`backend/engine/file_ops.py`
- 新增能力：
  - `cleanup_project_cache` / `cleanup_all_projects_cache`：清理過舊快取。
  - `delete_job_files`：刪除 job 時同步清理 image/pdf/preview 等檔案與快取。
  - `optimize_jxl_storage`：將非 JXL job 圖片轉為 JXL 並更新 DB 路徑與 metadata。
  - `detect_job_sub_rects` / `apply_job_resplit`：支援手動二切偵測與套用（新 job 生成 + 舊 job 清除）。
- 檔案：`backend/engine/core.py`
- 調整：
  - `delete_job` 改為先執行檔案清理，再刪 DB，回傳結構化結果。
  - 新增 `cleanup_preview_cache`、`optimize_jxl_storage_all_projects`、`detect_job_sub_rects`、`apply_job_resplit` 委派。

### 2.5 API 與啟動生命週期

- 檔案：`backend/routers/jobs.py`
- 新增端點：
  - `POST /api/projects/{project_id}/jobs/{job_id}/detect-sub-rects`
  - `POST /api/projects/{project_id}/jobs/{job_id}/apply-resplit`
- 檔案：`backend/main.py`
- 調整：
  - lifespan 啟動後以背景任務執行：
    - 預覽快取清理
    - 全專案 JXL 優化

### 2.6 前端手動二切介面

- 檔案：`frontend/src/components/ResplitModal.vue`（new）
- 功能：
  - 顯示目前影像與候選區域。
  - 支援角點拖曳、區域新增與刪除。
  - 一鍵提交 `apply-resplit`。
- 檔案：`frontend/src/views/ProjectDetailView.vue`
- 調整：
  - 在 job 操作列新增「手動二切」按鈕，整合 modal 開啟與刷新流程。
- 檔案：`frontend/src/services/api.js`
- 調整：
  - 新增 `detectJobSubRects` 與 `applyJobResplit` API 封裝。
