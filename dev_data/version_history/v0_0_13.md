# v0.0.13

日期：2026-04-04

## 1. 主題

JXL 全鏈路相容性（方案 A：擴充 Adapter）

本版目標是讓後端所有關鍵圖片讀取路徑都能處理 JXL，並將讀取邏輯集中到統一入口，避免散落式分支造成維護風險。

---

## 2. 實作摘要

### 2.1 ImageCodecAdapter 擴充讀取端

- 檔案：`backend/processing/image_codec_adapter.py`
- 新增：
  - `read_image(path)`：統一回傳 OpenCV 慣例 BGR `np.ndarray`，直接轉發到 `utils.cv_imread_chinese`。
  - `read_image_pil(path)`：統一回傳 PIL RGB Image；遇到 `.jxl` 走 `imagecodecs.jpegxl_decode`。
- 設計：
  - 依 v0.0.13-opt，避免與 `utils` 重複實作 Numpy 讀取邏輯。

### 2.2 底層讀取工具強化

- 檔案：`backend/utils/utils.py`
- `cv_imread_chinese(filepath)`：
  - `.jxl` 分支使用 `imagecodecs.jpegxl_decode`。
  - RGB 結果轉為 BGR（OpenCV 慣例）。
  - 其餘格式維持 `cv2.imdecode(np.fromfile(...))`。

### 2.3 FileOps 白名單與預覽路徑修復

- 檔案：`backend/engine/file_ops.py`
- 修正點：
  - `_prepare_tasks` 支援 `.jxl` 原始圖。
  - `add_project_files` 轉檔白名單加入 `.jxl`。
  - `_render_preview` 改為統一走 `ImageCodecAdapter.read_image_pil()`，移除手寫 JXL 分支。

### 2.4 Voucher PDF 產生器 JXL 相容化

- 檔案：`backend/engine/voucher_generator.py`
- 修正點：
  - `_image_stream_for_rect` 改用 `ImageCodecAdapter.read_image_pil()`。
  - 新增 `_image_stream_from_pil()`，統一控制縮放與 JPEG stream 生成。
  - `generate_voucher_pdf`：
    - 不再使用 `fitz.Pixmap(path)` 讀圖。
    - 不再用 `insert_image(filename=...)`。
    - 改為先透過 Adapter 讀取，再 `insert_image(stream=jpeg_bytes)`。

### 2.5 Voucher Router 重複邏輯收斂

- 檔案：`backend/routers/voucher.py`
- `_load_image_bytes` 改為統一使用 `ImageCodecAdapter.read_image_pil()`。
- 移除 router 內手寫 `.jxl` 分支，降低重複實作。

### 2.6 __main__ 測試入口修補（低優先）

- 檔案：
  - `backend/processing/qr_handler.py`
  - `backend/processing/rapidocr_handler.py`
  - `backend/processing/vision_handler.py`
- 三者 `__main__` 讀圖由 `cv2.imread` 改為 `cv_imread_chinese` 路徑，提升中文路徑與 JXL 手動測試可用性。

## 5. 風險與備註

1. JXL 仍依賴 `imagecodecs`，若環境未安裝，JXL 讀取會失敗（標準格式不受影響）。
2. 目前全量 pytest 有一個既有模組缺失問題（`scripts.migrate_db_flatten_jobs`），需另案補齊或調整該測試收集條件。
3. 本版已將關鍵讀取路徑集中於 Adapter + utils，後續若擴充 HEIF/其他格式，改動面可維持最小化。
