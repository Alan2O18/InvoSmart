# v0.0.10

日期：2026-03-15

## 主題

全生命週期工作流架構升級（影像管線、非同步強化、資料品質防護）。

---

## 更新重點

### Phase 1：憑證 DB 資料源整合與旋轉重置防護

1. **憑證產生即時從 DB 取值**
   - `backend/routers/voucher.py` `generate` 端點改為每次從 `job_repo.get_display_result()` 重新拉取最新文字（`amount`、`payDate`、`receiptCount`、`purpose`）。
   - 防止前端排版 Canvas 帶有過時快照資料（尤其使用者在排版中途回去 Job Editor 修改金額後）。
   - 不信任前端傳入的文字內容，嚴格遵守「前端只傳 x/y/scale 座標，後端從 DB 取真實值」的安全合約。

2. **影像旋轉強制清除 Job 資料**
   - `FileOps.rotate_image()` 轉非同步 (async)；旋轉完成後自動找出與此圖片對應的 Job，強制重置：
     - `status → pending`
     - `vlm_result_json / manual_json_text / validation_json / vlm_stats → None`
     - `qr_verified → 0`
   - 防止 VLM 舊座標（x,y,w,h）在圖片旋轉後繼續被使用造成框選錯位。
   - `Engine.rotate_image()`、`routers/files.py` rotate 端點同步改為 async；相關測試改用 `AsyncMock`。

---

### Phase 2：非同步扁平化架構與並發保護

1. **Word 報表快取扁平化**
   - 新增 `engine/word_exporter.py` per-project 快取檔案 (`cache/flattened_items.json`)。
   - 快取包含來源簽章（所有 `done` Job 最後更新時戳之合集）；若簽章未變則直接使用快取，避免每次匯出重新壓平。
   - `save_manual_json` 端點儲存後觸發 best-effort asyncio.create_task 預先重建快取。

2. **影像處理並發限制器**
   - `Engine` 新增 `image_processing_semaphore`（`asyncio.Semaphore`）。
   - 設定鍵：`processing_settings.image_conversion_max_concurrency`（預設 3）。
   - 分割管線中的 `cv_imread + splitter.split` 若能取得 Semaphore 則在其保護下執行，防止大量並發上傳觸發 OOM。

3. **非同步防呆**
   - `run_word` export facade 加入 `inspect.isawaitable` 守衛，使同步 mock 與非同步真實實作都能正確執行（避免測試與執行環境不一致）。

### Phase 3：影像管線升級（Preview Cache + Codec Adapter + JXL）

#### P3-1：前端快取影像管線

1. **Preview 快取管理器**
   - `FileOps` 新增 `ensure_preview_cache()`、`invalidate_preview_cache()` 方法。
   - 快取目錄：`{project_root}/快取影像/voucher_preview/`
   - 快取檔名簽章：`{stem}_{mtime_ns}_{filesize}_{max_width}.{ext}`，避免舊圖誤用。
   - 編碼優先序（依 Pillow 能力探測）：AVIF → WebP → JPEG。

2. **分割/收檔流程預熱快取**
   - `run_splitting()` 與 `add_project_files(type=split)` 在 enqueue job 之前主動預熱縮圖快取。
   - 預熱失敗不阻斷主流程（只記 warning），保護業務可用性。
   - 所有縮圖轉檔操作共用 `image_processing_semaphore`，防止高並發記憶體尖峰。

3. **旋轉後快取失效與重建**
   - `rotate_image()` 旋轉完成後先清除舊 preview 快取（glob `{stem}_*`），再重建新快取。
   - 確保前端載入到的縮圖永遠是旋轉後的正確版本。

4. **Voucher 取圖 API 快取優先**
   - `GET /api/voucher/{project_id}/image/{job_id}?thumb=true` 優先從 preview 快取回傳。
   - 快取命中 → 直接 `FileResponse`；快取失敗 → fallback 即時縮圖（相容舊行為）。

#### P3-2：Codec Adapter 與 JXL 管線

1. **可插拔 Codec Adapter**
   - 新增 `backend/processing/image_codec_adapter.py`（`ImageCodecAdapter`）。
   - 統一 archival format 決策，與 `file_ops` 業務邏輯解耦。
   - `resolve_archival_extension()` 依序：讀設定 → 探測 JXL encoder → 決定副檔名（JXL 不可用時降回 `.jpg` 並記 warning）。
   - `write_archival_image()` for `.jxl`：透過臨時 PNG 轉接 pyvips 管線；pyvips 失敗則安全降回 `.jpg`。

2. **JXL Encoder Backend**
   - 新增 `backend/processing/jxl_encoder_backend.py`。
   - `is_jxl_available()`: 探測 pyvips 是否安裝且 libjxl 可用（寫入一個 2×2 測試圖來驗證），結果模組層級快取（process lifetime）。
   - `encode_to_jxl(source, output, quality=85)`: 封裝 pyvips JXL 寫入；encoder 不可用時拋 `RuntimeError`（明確而非靜默產生壞檔）。
   - ⚠️ Windows 環境下 Pillow 原生不支援 JXL；需另行安裝 pyvips + libjxl 才能啟用。

3. **Job 資產元資料顯式化**
   - `backend/database/models.py` 的 `Job` ORM 新增欄位：
     - `source_format`（`String`, nullable）：存檔格式，如 `"jpg"`, `"jxl"`, `"png"`
     - `preview_cache_path`（`String`, nullable）：最新 preview 快取的絕對路徑
   - `backend/repositories/job_repository.py` `get_job()` 回傳字典補上兩欄。
   - Alembic migration：`b3f7a2c91de0_add_asset_metadata_to_jobs.py`（接續 `06607c99f84c`）。

4. **分割流程寫入資產元資料**
   - `_prepare_tasks()` 與 `add_project_files(type=split)` 在 enqueue job 後即以 `update_job(job_id, source_format=..., preview_cache_path=...)` 寫回 Job 記錄。
   - 寫入失敗不阻斷主流程（只記 warning）。

5. **Migration 腳本（歷史專案升級）**
   - `scripts/migrate_images_to_jxl_avif.py` 功能：
     - `--dry-run`：預覽動作但不寫出任何檔案
     - `--resume`：根據 checkpoint 跳過已處理圖片
     - `--canary-limit N`：僅處理前 N 張（分批驗證 staged rollout 用）
     - `--report-path FILE`：完成後輸出 JSON summary（migrated/skipped/errors/timestamp）
     - 自動輸出 `.rollback.json`（列出本次新建的快取檔清單，供 rollback 批次刪除）
     - checkpoint 每 N 筆自動存檔（`--checkpoint-interval`，預設 100）
