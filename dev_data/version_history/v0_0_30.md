# v0.0.30 變更紀錄 (Changelog)

本版本主要優化 VLM 辨識的精確度與對帳機制，修正核心欄位覆蓋 Bug，並啟用 QR Code 的二次比對功能：

1. **預算品類限定 (VLM Category Constraint)**
   - 修改 `receipt_processor.py` 與 `workers.py` 處理迴圈。在辨識收據時，若存在 `project_id`，會自資料庫動態撈取專案之 `budgetExpense` 列出的經費品類列表。
   - 將該允許的分類列表作為 `prompt_context` 注入 LLM 辨識，並加入嚴格指令限制：*「items 陣列中每個項目的 category 欄位必須只能從以下列表中選擇，不得自行產生其他品類」*。有效解決 VLM 預想無關品類導致報表匯出分類混亂的問題。

2. **取消 VLM 預填與獨立化內部 ID (Decoupled Voucher ID & Invoice ID)**
   - 移除在 VLM 資料擷取後，因自訂 `voucher_id` 為空而強制將官方 `invoice_id` 複製至該欄位的行為，使「內部憑證編號」欄位預設保持乾淨為空。
   - 修正 `job_repository.py` 中 `_reconstruct_display_json` 方法。在向前端輸出 JSON 時，發票號碼不再強制覆蓋為 `voucher_id`，而是正確從 VLM/Manual 的 raw JSON 中取得 `invoice_id` 並獨立保存，解決儲存內部編號後發票號碼即被覆蓋丟失的 BUG。

3. **啟用 QR Code 二次對帳與驗證機制 (QR Secondary Reconciliation)**
   - **備份原始預測**：在 QR Code 資料合併前，備份 VLM 原始辨識的 `invoice_id`、`date`、`total` 欄位至 `verification` 結構中。
   - **對帳比對與計分 Bug 修正**：
     * 修正 `python_validator.py` 評分 Bug，改為檢查 `verification.qr_verified` 以正確計入 15% 的 QR 驗證可靠性加分。
     * 若 QR 驗證通過，自動比對 VLM 與 QR Code 的資料值。若有發票號碼、日期、總金額不符之情形，自動在 `validation.issues` 中列出警示（例如 `[QR對帳] 發票號碼不符: VLM='AB1234567B', QR='AB12345678'`）。
   - **前端狀態徽章**：修改 `JsonFieldEditor.vue`，在發票特徵區塊中，若 `qr_verified` 為真，顯示動態亮綠色的 **「🟢 已通過 QR 數位驗證對帳」** 徽章，大幅提升系統的對帳反饋性。

4. **解除封存功能與防錯機制 (Unarchive & Read-only Safeguards)**
   - **解除封存端點**：於 `projects.py` 新增 `POST /api/projects/{project_id}/unarchive` 端點，支援將已封存（`ARCHIVED` / `SEALED`）的專案狀態恢復回 `PROCESSED`（作用中）。
   - **按鈕自動切換**：在 `ProjectDetailView.vue` 詳情頁中，當專案已被封存時，原本的「封存活動」按鈕會自動切換為橘黃色的「解除封存」按鈕，使用者能一鍵點擊解除鎖定。
   - **唯讀防錯提示**：
     * 修改 `BudgetEditorView.vue`，若專案為封存狀態，頂部會顯示醒目的唯讀橫幅警告，且「儲存變更」按鈕將被禁用，避免編輯後送出遭遇 409 Conflict 錯誤。
     * 修改 `ProjectsOverviewView.vue`，若專案已封存，其展開面板中的「啟用編輯模式」核取方塊會被禁用並給出相應提示，全面防止對唯讀資料的無效寫入。
