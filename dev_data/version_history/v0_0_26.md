# v0.0.26 前端缺陷修復

**專案狀態**: ✅ 已完成

---

## 執行摘要

v0.0.26 修復了系統在發票建檔、手動分割與資料核對流程中的四項前端缺陷，主要改進了版面排版對齊的一致性、檔案路徑的編碼容錯性、路由跳轉的安全度，以及手動二切畫布加載時的非同步 Race Condition 問題。

---

## 主要修改項目

### 1. 返回按鈕對齊與樣式修整
- **對齊修正**：在 `VoucherEditorView.vue` 中，重設 `h2` 標題的預設 vertical margins 為 0，修復了 header 的垂直拉伸與對齊偏斜問題。
- **樣式覆蓋修正**：在 `VoucherEditorView.vue` 中將無資料狀態按鈕 class 改為 `empty-back-btn`，以防止樣式 specificity 被 `.back-btn` 和 `.empty-state-content button` 交錯覆蓋。
- **一致性微調**：將 `ProjectDetailView.vue` 的 `back-btn` 改為與系統一致的按鈕樣式，加入圓角與 Hover 動態背景效果。

### 2. 圖片旋轉與刪除支援中文檔名
- **URL 編碼**：在 `api.js` 中對 `deleteRawFile`、`rotateImage` 與 `runSplitSingle` 中的 `filename` 參數，全面套用 `encodeURIComponent`，避免在傳入含中文字元或特殊符號的檔名時引起 FastAPI 路由比對失敗。

### 3. 憑證編輯器與核對資料命名路由跳轉
- **Vue Router 命名路由**：在 `ProjectDetailView.vue` 中，將 path-based 跳轉改為 named router 寫法 `router.push({ name: 'voucher-editor', params: { id: projectId }, query: { editJobId: job.job_id } })`，以提升在多層級路徑下的傳參穩定性。

### 4. 手動二切畫布座標加載 Race Condition 修復
- ** Race Condition 解決**：在 `ResplitModal.vue` 的 `fetchDetectedRects` 函數中，若圖片尚未觸發 `@load` 加載成功 (`naturalSize.width === 0`)，則不在 API 請求結束時立刻套用預設的 `100x100` 切割方塊。取而代之的是將 `rects.value` 設為 `[]`，待圖片加載完畢後，再根據大圖的正確比例動態初始化，徹底解決了二切區域縮水、漂移至左上角而無法調整的問題。
- **連接埠解耦**：將 Modal 內部的 `http://localhost:8000` hardcoded 前綴改為調用 `api.toAbsoluteUrl`，以動態對齊後端 API 設定網址。
