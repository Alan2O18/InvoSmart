# v0.0.12

日期：2026-03-29

## 主題

JXL 編碼管線修正與預覽影像全鏈路修復。

---

## 背景

v0.0.10 完成 JXL 管線的程式碼架構與 pyvips 整合，但實際上線後遭遇兩個關鍵阻塞：

1. **pyvips DLL 相容問題**：Windows 環境下 `pyvips` 載入 `libvips-42.dll` 時與 conda 環境衝突，導致 JXL encoder 無法初始化。
2. **預覽圖全面失效**：當分割發票以 `.jxl` 格式存檔後，前端與 voucher 的所有圖片預覽均無法顯示。

本版全面修復上述問題，並將 JXL 編碼效能優化 43 倍。

---

## 更新重點

### 1. JXL 編碼器後端切換：pyvips → imagecodecs

- **根因**：pyvips 在 Windows micromamba/conda 環境下 DLL 載入失敗（`libvips-42.dll` 路徑衝突），無法穩定使用。
- **處置**：將 JXL 編碼後端從 `pyvips` 切換為 `imagecodecs`（純 Python wheel，自帶 libjxl binding，無外部 DLL 依賴）。
- **修改檔案**：
  - `backend/processing/jxl_encoder_backend.py`：
    - `is_jxl_available()` 改為探測 `imagecodecs.jpegxl_encode` 是否可用。
    - `encode_image_to_jxl(image, output_path)` 新增直接接受 numpy array 的 API，避免中間 PNG 磁碟 I/O。
    - `encode_to_jxl()` 保留為相容 wrapper，內部改用 `cv_imread_chinese()` + `encode_image_to_jxl()`。
  - `backend/processing/image_codec_adapter.py`：
    - `write_archival_image()` 改用 `encode_image_to_jxl()` 直接編碼 numpy array，移除臨時 PNG 寫出邏輯。
    - 新增 3 次重試 fallback 機制。
    - 修正警告訊息中殘留的 `pyvips` 字串。

### 2. JXL 編碼效能優化（43 倍加速）

- **根因**：`imagecodecs.jpegxl_encode()` 預設 effort 為 5，單張 4959×7016 圖片耗時約 23 秒。
- **處置**：將 effort 設為 1。
- **實測對照**（以 `114-2燕巢小宏遠一.1.png` 為例，原始 PNG 35.5MB）：

| Effort | 耗時 | 檔案大小 | 相對省空間 |
|--------|------|---------|-----------|
| 1 | **0.53s** | 18,898 KB | 47% |
| 3 | 4.79s | 15,600 KB | 56% |
| 5 (預設) | 22.7s | 16,081 KB | 55% |
| 7 | 42.5s | 15,798 KB | 55% |

- **結論**：effort=1 速度快 43 倍，檔案僅大 18%，為最佳性價比選擇。

### 3. 預覽影像全鏈路修復

#### 3.1 根因分析

兩條顯示路徑皆斷：

1. **直接 URL 路徑**：前端使用 `/static/.../分割發票/filename.jxl` 直接請求圖片，但主流瀏覽器（Chrome, Firefox）**不原生支援 JXL 渲染**。
2. **Preview Cache 路徑**：`ensure_preview_cache()` 使用 `PIL.Image.open()` 讀取源檔再縮小輸出 AVIF/WebP，但 **Pillow 無法辨識 `.jxl` 格式**（實測回傳 `cannot identify image file`）。

結果：
- 後端快取目錄無任何快取檔案（生成失敗被 `except` 靜默吞掉）。
- 前端 `<img>` 標籤載入 `.jxl` 原始檔，瀏覽器無法解析。

#### 3.2 修復方案

**後端 — 3 個 JXL-aware 讀取點**

| 檔案 | 函式 | 修改 |
|------|------|------|
| `backend/engine/file_ops.py` | `_render_preview()` | 偵測 `.jxl` 副檔名 → `imagecodecs.jpegxl_decode()` → `Image.fromarray()` |
| `backend/routers/voucher.py` | `_load_image_bytes()` | 同上 |
| `backend/routers/files.py` | 新增 2 個端點 | 見下方 |

**後端 — 新增 Preview 代理端點**

前端原先直接走 `/static/` 拿原始檔。但 JXL 瀏覽器不認，且 Static Files 不經過任何轉碼邏輯。新增兩個 API 端點，透過 `ensure_preview_cache()` 提供瀏覽器可用的 AVIF/WebP/JPEG：

```
GET /api/projects/{project_id}/preview/split/{filename}
GET /api/projects/{project_id}/preview/raw/{filename}
```

**前端 — 3 個 View 的 URL 修正**

| 檔案 | 函式 | 舊 URL | 新 URL |
|------|------|--------|--------|
| `ProjectDetailView.vue` | `getImageUrl()` | `/static/{id}/分割發票/{file}` | `/api/projects/{id}/preview/split/{file}` |
| `ProjectDetailView.vue` | `getRawImageUrl()` | `/static/{id}/原始輸入/{file}` | `/api/projects/{id}/preview/raw/{file}` |
| `KanbanView.vue` | `getImageUrl()` | `/static/{id}/分割發票/{file}` | `/api/projects/{id}/preview/split/{file}` |
| `JobEditorView.vue` | `imageUrl` | `/static/{id}/分割發票/{file}` | `/api/projects/{id}/preview/split/{file}` |
| `JobEditorView.vue` | `preloadImage()` | `/static/{id}/分割發票/{file}` | `/api/projects/{id}/preview/split/{file}` |

## 錯誤修復

- **預覽圖全部顯示為空白**：JXL 源檔案 PIL 無法開啟 + 瀏覽器不支援 JXL → 改為 imagecodecs 解碼 + API 代理端點提供 AVIF/WebP 預覽。
- **JXL 轉檔極慢（每張 ~23 秒）**：預設 effort 過高 → 設為 effort=1（0.5 秒）。
- **image_codec_adapter.py 殘留 pyvips 警告文字**：log 訊息修正為 `imagecodecs`。
- **test_routers_voucher.py 斷言過期**：`voucherNo.point` 已從 `[78, 255]` 微調為 `[78.5, 255]`，`paymentAmount.point` 從 `[310, 785]` 修正為 `[314, 785]`。
- **test_jxl_encoder_backend.py mock 路徑錯誤**：
  - `test_encode_to_jxl_raises_when_unavailable`：改為測試 `encode_image_to_jxl` 直接 API（`encode_to_jxl` wrapper 會在 mock 前觸發檔案讀取）。
  - `test_encode_to_jxl_wrapper`：mock 路徑從 `jxl_encoder_backend.utils.cv_imread_chinese` 修正為 `backend.utils.utils.cv_imread_chinese`（因 `utils` 是函式內 lazy import，非模組屬性）。
