# 收據處理流程 (Receipt Processing Pipeline)

> **版本**: 2026-01-05

---

## 流程總覽

```
掃描 A4 原稿
    ↓
分割為單張發票
    ↓
OCR 識別
    ↓
發票分類
    ↓
┌─────────────────┬─────────────────┬─────────────────┐
│  A 手寫收據      │  B 電子發票      │  C 其他          │
│  (免用統一發票)   │                 │  (傳統發票/證明) │
└────────┬────────┴────────┬────────┴────────┬────────┘
         ↓                 ↓                 ↓
    OCR 重排版         OCR 重排版         OCR 重排版
         ↓                 ↓                 ↓
    LLM 智慧修正      QR Code 掃描       LLM 提取 JSON
    (全域詞庫比對)          ↓                 ↓
         ↓           LLM 比對填補          ┌─┘
    LLM 提取 JSON          ↓              │
         ↓                 ↓              │
         └────────────────→←──────────────┘
                          ↓
                   存檔 JSON
                   標記信心度
                   人工查核
```

---

## 詳細步驟

### Stage 1: 前處理

| 步驟 | 說明 | 模組 |
|-----|------|------|
| 1.1 | 掃描 A4 → 分割單張發票 | `receipt_splitter.py` |
| 1.2 | OCR 識別 | `rapidocr_handler.py` |
| 1.3 | 關鍵字分類 | `keyword_classifier.py` |

---

### Stage 2: 分流處理

#### 路徑 A：手寫收據

```
OCR 結果 → 重排版 → LLM 修正 → LLM 提取 → JSON
```

| 步驟 | 說明 |
|-----|------|
| A.1 | OCR 文字重排版 (版面重建) |
| A.2 | LLM 智慧修正：比對**全域詞庫** (曾出現的買受人、店家名) |
| A.3 | LLM 猜測/補全缺字 (例：師大學 → 師範大學) |
| A.4 | LLM 提取結構化 JSON |

> **信心度**: 根據修正幅度與匹配程度計算

---

#### 路徑 B：電子發票

```
OCR 結果 → 重排版 → QR 掃描 → LLM 比對 → JSON
```

| 步驟 | 說明 |
|-----|------|
| B.1 | OCR 文字重排版 |
| B.2 | QR Code 掃描與解析 |
| B.3 | LLM 比對 OCR 與 QR 資料 |
| B.4 | 填補缺失欄位 (QR 無品項明細時從 OCR 補) |

> **信心度**: QR 解析成功 → 高；需 LLM 補全 → 中

---

#### 路徑 C：其他 (傳統發票/印刷證明)

```
OCR 結果 → 重排版 → LLM 提取 → JSON
```

| 步驟 | 說明 |
|-----|------|
| C.1 | OCR 文字重排版 |
| C.2 | LLM 直接從文字提取結構化 JSON |

> **信心度**: 格式標準 → 高；格式混亂 → 低

---

### Stage 3: 收尾

| 步驟 | 說明 |
|-----|------|
| 3.1 | 儲存 JSON 到資料庫 |
| 3.2 | 計算並標記**信心度** (0-100%) |
| 3.3 | 標記狀態為「待查核」 |
| 3.4 | 優先顯示低信心度項目供人工檢查 |

---

## 信心度機制

| 等級 | 分數 | 說明 | UI 顯示 |
|-----|------|------|---------|
| 🟢 高 | 80-100% | 資料完整、QR 成功、格式標準 | 綠色標籤 |
| 🟡 中 | 50-79% | 部分修正、需少量補全 | 黃色標籤 |
| 🔴 低 | 0-49% | 大量修正、格式混亂、缺失欄位 | 紅色標籤 |

**影響因素**:
- OCR 識別信心度
- LLM 修正幅度 (修正越多，信心度越低)
- 必填欄位完整度
- QR 解析成功與否
- 驗算結果 (金額加總是否正確)

## 全域詞庫

儲存於 `global_projects.db` 中，包含：

| 詞庫 | 用途 |
|-----|------|
| 買受人名單 | 修正/猜測買受人欄位 |
| 店家名稱 | 修正/猜測店章欄位 |
| 商品品項 | 修正常見品項名稱 |

> LLM 在 Prompt 中參考詞庫內容進行修正
